# 内容更新说明

一句话：**新增一篇文章 = 新建一个 Markdown 文件**。文件名就是 slug，路由、阅读时长、摘要、封面、排序、上下篇都由系统生成，作者只写内容。

## 一、三步流程

1. 新建文件 `src/content/insights/<slug>.md`。slug 用英文小写与连字符，例：`first-paid-user.md`。
2. 写 frontmatter，最少需要三行：`title`、`category`、`date`。
3. 用 Markdown 写正文，保存，构建完成即上线（草稿除外）。

不需要：手填 id、阅读时长、摘要、排序、封面路径、上下篇。

## 二、frontmatter 字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `title` | 是 | 文章标题，建议 15–25 字，写判断不写「浅谈」。 |
| `tagline` | 否 | 标题下方的一句副标题，14–16px 弱化显示；不写则不渲染。 |
| `category` | 是 | 四选一：`90天实战`、`产业数字化`、`AI 与产品`、`技术与管理`。写错会在构建时报错，不会静默归入「全部」。 |
| `topic` | 否 | 三选一：`个人商业创造`、`AI与产品创造`、`个人商业系统`。不写 = 不进入方向筛选与专题页聚合。 |
| `date` | 是 | `2026.11.12` 或 `2026-11-12`。用于确定发布日期与排序。 |
| `draft` | 否 | `true` = 草稿，默认 `false`。 |
| `cover` | 否 | 一般不用写。写 `/xxx.webp` 用 public 下的图；写文件名则按 slug 查找。 |
| `excerpt` | 否 | 覆盖自动摘要。不写则取正文第一段。 |
| `takeaways` | 否 | 核心观点数组，3–5 条；一条一张卡，在标题下方单卡展示，读者可通过圆点、方向键或触控手动切换，不自动轮播；不写或空数组时退回默认单图封面。 |
| `tags` | 否 | 关键词数组，3–5 个；不写则文末不渲染标签。 |

## 三、最小示例（6 行）

```md
---
title: "我为什么先做一件小事"
category: "90天实战"
date: "2026.11.12"
---

正文第一段直接写。这一段会自动成为列表摘要与详情页导语。
```

保存为 `src/content/insights/why-small-first.md`，访问地址就是 `/insight/why-small-first/`。

## 四、自动推导规则

| 内容 | 规则 |
| --- | --- |
| slug / 路由 | 由文件名生成，`/insight/<slug>/`；改名等于改地址，旧链接会 404。 |
| 阅读时长 | 中文按字、英文按词，约 380 字/分钟，向上取整，最少 1 分钟。 |
| 摘要 | 取正文第一段纯文本，截到 80–90 字并以句号收尾；第一段本身较短则原样使用。可用 `excerpt` 覆盖。 |
| 排序 | 按 `date` 倒序；首页「最新洞察」取已发布的前三篇，列表顶部同序。不再依赖数组顺序。 |
| 封面 | 用 `npm run covers` 生成 `<slug>-1.webp`，作为列表缩略图与 `og:image`；找不到用统一默认封面。 |
| 上下篇 | 同 `category` 内按日期排序，自动生成上一篇 / 下一篇。 |
| 草稿过滤 | `draft: true` 的文章不出现在任何列表、首页、专题页、90 天记录与计数里。 |

## 五、正文写法

正文是标准 Markdown，详情页直接渲染：

- `## 小标题`：分节，建议 4–6 节；不要用 `#`（页面已有一级标题）。
- 空行分段，每段 1–4 句；正文由 Astro 原生 Markdown 渲染，第一段保持正常正文样式，不会被自动拆段或改写。
- 支持标题、段落、有序/无序列表、`>` 引用、`[链接](https://…)`、`**加粗**`、代码块、表格与图片。
- 不要在正文里重复标题；标题已在 frontmatter 里。

### 核心观点（takeaways）与副标题（tagline）

- 条数：3–5 条，一句话一条。只写正文里已经出现的判断，不新增观点，不拔高，不写成励志短句。
- 形态：H1 下方只有**一个卡片**（与正文同宽、居中），卡内一次显示一条观点，读者手动切换。
- 卡片内容：大字观点 + 分类 + 序号（如 `2 / 4`）+ 品牌署名「个人商业创造者」。
- 切换：不自动播放，避免阅读中途内容自行变化；右下角圆点可点击跳到对应观点，聚焦卡片后可用左右方向键切换，触屏可左右滑动。
- 颜色：全站统一主色 `#D8F26B`（荧光笔绿）。4 张卡在同一色相内逐张提亮 5%（68.4% → 73.4% → 78.4% → 83.4%），文字统一深色；切换时底色与文字一起淡入淡出。
- 无障碍：`prefers-reduced-motion` 下关闭淡入淡出，圆点仍可点击；禁用 JS 时圆点隐藏，卡内按顺序纵向堆叠显示全部观点，不会只剩第一条。
- 顺序：第 1 条既是进入页面时的默认视图，也是 `og:image` 与列表缩略图，所以把最有钩子的那条放第一位。
- 只有 1 条：顶部卡片只有一屏、不出现圆点；不写或写成 `[]` 时，顶部退回默认单图封面。
- `tagline` 可选，渲染在标题下方，一句结论式副标题；不写则不渲染。

## 六、封面

- 封面是「纯色底 + 大字观点」的图形封面，不使用照片或随机生成图。每篇文章只生成 1 张：`<slug>-1.webp`。
- 这张图用于洞察列表缩略图与 `og:image` / `twitter:image`。页面顶部的观点卡是 HTML 渲染的单卡手动切换，不引用图片，所以不再逐条出图——避免仓库和构建产物里留下无引用的文件。
- 主文案取 `takeaways[0]`，右上角序号写 `1 / N`；尺寸 1600×1000（16:10），WebP，单张 ≤120KB。
- 颜色：所有封面统一主色 `#D8F26B`（荧光笔绿，`hsl(71.6 83.9% 68.4%)`），按明度阶梯第 1 档最深、逐张提亮 5%；文字用近黑 `rgba(12,12,12,.92)`，次要信息 `.72`。色值与页面卡片共用 `src/lib/cover-palette.mjs`，不在模板里另外硬编码。
- 生成：先写好 md 与 `takeaways`，运行 `npm run covers`（默认只处理已发布文章），或 `npm run covers -- <slug>` 指定单篇。脚本用系统 Edge 无头截图，再经 sharp 压成 WebP，无需额外安装浏览器。
- 模板在 `scripts/cover-template.html`；生成脚本按主色明度阶梯取色、按文案长度选字号。重新运行会先删掉该篇旧图，不会残留。
- 不写封面也能发布：自动使用 `src/assets/covers/_default.svg`（深色 + 绿色节点，与全站一致）。
- 原图可放 `covers-originals/`（已 gitignore）。

## 七、草稿与发布

- 写稿时加 `draft: true`：文章不进任何列表，详情页带「草稿 · 未发布」角标和 `noindex,nofollow`；仍可通过 `/insight/<slug>/` 直链预览。
- 发布：删除 `draft` 这一行（或改 `false`），重新构建。
- 撤回：加回 `draft: true`。列表立刻消失，但直链仍可打开——不要把 `draft` 当保密手段。
- 删除文章：删掉 md 与同名封面，重新构建。旧地址会返回 404。

## 八、构建、预览与上线

```powershell
npm install      # 首次
npm run dev      # http://localhost:4321/
npm run build    # 产物在 dist/，输出 page(s) built
npm run preview  # 预览 dist/
```

当前生产部署以仓库 README 中的 EdgeOne Pages 配置为准：构建命令 `npm run build`，输出目录 `dist`，推送到连接的生产分支 `main` 后自动构建发布。



## 九、旧链接与 404

- 旧版 `/insight/?id=N` 会跳到对应的 `/insight/<slug>/`，映射在 `src/data/legacy-ids.mjs`，不要修改已发布的映射。
- 不存在的 slug 返回 404（`src/pages/404.astro`），不会兜底显示别的文章。

## 十、发布前自查

1. `npm run build` 通过。
2. 列表出现新卡片，位置符合日期倒序。
3. `/insight/<slug>/` 的标题、日期、分类、阅读时长、摘要、正文、上下篇正确；顶部单卡与文末整卡的条数、序号（`1 / 4`）和 `takeaways` 一致，第 1 条与列表缩略图相同；草稿角标符合状态。
4. 分类与方向筛选计数 +1；专题页聚合到（`topic` 精确匹配）。
5. 首页「最新洞察」是否出现（取决于日期是否在前三）。

## 十一、改页面固定文案

- 首页 `src/pages/index.astro`、关于 `src/pages/about.astro`、洞察列表 `src/pages/insights.astro`
- 专题导语 `src/data/topics.mjs`、90 天阶段 `src/data/stages.mjs`
- 分类与方向清单 `src/lib/taxonomy.ts`（改这里会同步影响筛选与校验）

文案以 `brand/品牌表达系统_V1.md` 为准；公开披露按品牌表达系统的三层边界逐项判断：可以写行业、角色职责、方法论及经确认可公开的成果量级；涉及具体产品名、技术栈和组织分工时谨慎判断是否可识别；不写客户名、内部数据、未公开规划、同事姓名及可识别的内部系统架构。不能把所有数字一概视为禁止项，也不能把匿名化当作自动安全。

## 十二、发布后：三平台产物（自动）

新增一篇 `insights/<slug>.md` 并 push 到 `origin/main` 之后，**自动**出三份外部平台产物，不需要另外交代：

| 渠道 | 链路 | 落盘 |
| --- | --- | --- |
| 公众号 | 站点 md 原文排版（`wechat-layout`） | `output/<日期>/微信公众号/<slug>/` |
| 小红书 | 3:4 原文卡片（`image-cards`） | `output/<日期>/小红书/<slug>/` |
| 抖音 | 3:4 图文卡组（同源，不重改写） | `output/<日期>/抖音/<slug>/` |

- 只对「新增文章 + push 上线」触发。改站点功能、改已有文章字段、只 `build` 不推送、仓库整理等**都不触发**。
- 草稿（`draft: true`）push 了也不触发。口播视频默认不做，点名才做。
- 触发来源：`scripts/githooks/pre-push`（本仓库 `core.hooksPath=scripts/githooks`）。推送 `main` 且带新增文章时，它往 `output/publish-watch.log` 写一行，产物由这一行驱动。钩子永不阻断推送；换电脑或重克隆后需重设一次 `git config core.hooksPath scripts/githooks`。
- 完整判定、命令、验收与台账见 `docs/工作流_文章上线即出三平台_v1_2026-11-12.md`，记录写在 `output/publish-watch.log` 与 `output/发布台账.md`。
