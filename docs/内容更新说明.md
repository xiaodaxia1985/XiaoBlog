# 内容更新说明

本说明对应站点仓库 `XiaoBlog`（Astro 静态站点），部署在 Cloudflare Pages 根域。日常内容更新只涉及洞察数据和图片，不需要改页面模板。

## 一、新增一篇洞察

### 1. 数据文件

洞察不是传统的 Markdown + frontmatter 结构，而是集中存放在：

```
src/data/insights.mjs
```

文件里导出一个 `insights` 数组，每篇文章是数组里的一个对象。新增文章就是在数组末尾追加一个对象（注意用英文逗号与上一篇分隔）。

### 2. 字段说明

| 字段 | 类型 | 作用 | 写法建议 |
| --- | --- | --- | --- |
| `id` | 数字 | 文章唯一编号，详情页地址为 `/insight/?id=编号` | 在现有最大值上 +1，不要重复 |
| `category` | 字符串 | 栏目名，决定列表页筛选归属 | 从现有四个栏目中选一个：`90天实战`、`产业数字化`、`AI 与产品`、`技术与管理` |
| `date` | 字符串 | 发布日期 | `2026.11.08` 这种点分格式，与列表页展示一致 |
| `readTime` | 字符串 | 预计阅读时长 | 如 `8 分钟`，按正文长度估算 |
| `title` | 字符串 | 文章标题 | 具体、有判断，不用问句堆叠；建议 15–25 字 |
| `excerpt` | 字符串 | 列表卡片摘要 + 详情页 description | 一到两句话，写清文章解决什么问题；60–100 字 |
| `tagline` | 字符串 | 详情页标题下的一句话观点 | 一句话给出核心结论 |
| `image` | 字符串 | 封面图路径 | 以 `/` 开头，如 `/insights/insight-11.webp` |
| `lead` | 字符串 | 详情页导语 | 一段话交代背景与问题，100–200 字 |
| `sections` | 数组 | 正文分节 | 每节 `{ title, paras: [] }`，`paras` 是段落字符串数组 |
| `takeaways` | 数组 | 核心观点清单 | 3–5 条，每条一句话 |
| `tags` | 数组 | 文末标签 | 3–5 个关键词 |

可直接复制现有任意一篇的结构，改内容即可。

### 3. 图片放哪

- 图片统一放在 `public/insights/`。
- 文件名建议 `insight-编号.webp`，与 `id` 对应，便于维护。
- 数据里写根路径：`image: '/insights/insight-11.webp'`，不要带完整域名。
- 建议尺寸 1600×900（16:9），转成 WebP，单张控制在 150KB 以内。
- 原图可以另存到仓库根的 `covers-originals/`（不参与构建），压缩出问题时可回退。

### 4. 标题与摘要怎么写

- 标题：写判断和结论，不写“浅谈”“关于……的思考”这类空词。
- 摘要：第一句说清文章讨论的具体问题，第二句说清读完能得到什么；不要重复标题。
- 栏目：同一篇只归一个栏目，避免跨栏目重复投放。
- 标签：用读者会搜索的词，不用内部项目代号。

### 5. 改完要检查的地方

- 洞察列表页 `/insights/` 是否出现新卡片，排序是否符合预期（当前按数据顺序展示）。
- 列表页顶部的栏目筛选是否会随新分类正确计数（`?category=` 参数可直接跳转到对应栏目）。
- 点进详情页 `/insight/?id=新编号`，确认标题、封面、正文、核心观点都在。
- 首页导航「洞察」入口正常。

## 二、本地预览

首次使用先安装依赖（需要 Node.js 18 以上）：

```powershell
npm install
```

启动开发服务器：

```powershell
npm run dev
```

浏览器打开 `http://localhost:4321/`。改文件会热更新。

发布前做一次本地构建预览，确认和线上一致：

```powershell
npm run build
npm run preview
```

- `npm run build` 产物在 `dist/`，正常应输出 `6 page(s) built` 且 `Complete!`，无报错无警告。
- `npm run preview` 默认地址 `http://localhost:4321/`。

## 三、推送后多久上线

仓库已接入 Cloudflare Pages 的 Git 自动构建：推送到部署分支后，Cloudflare 会自动拉取、安装依赖并执行 `npm run build`，成功后发布。

- 通常 1–3 分钟上线，以 Cloudflare 控制台的构建日志为准。
- 如果构建失败，线上仍是上一个成功版本，不会出现半成品页面。
- 上线后如仍看到旧内容，先强制刷新（Ctrl+F5）排除浏览器缓存。

## 四、改错了怎么回滚

按影响范围从轻到重：

1. **单篇内容出错**：直接修改 `src/data/insights.mjs` 对应字段，重新推送即可，不需要回滚。
2. **整次发布要撤销，且不想动代码历史**：Cloudflare 控制台 → 项目 → Deployments，找到上一个正常版本，执行 Rollback。线上会立即回到该版本。
3. **代码层面撤销**：本地执行 `git revert <出问题的提交哈希>`，解决冲突后重新推送，Cloudflare 会重新构建。
4. **图片误传**：删除 `public/insights/` 下对应文件并同步修改数据里的 `image` 字段，再推送。

回滚后建议再走一遍「本地预览」里的构建与页面检查，确认恢复到的版本内容正确。

## 五、改页面文案（非日常操作）

首页、关于页、洞察列表页的固定文案分别在这些文件里：

- 首页：`src/pages/index.astro`
- 关于页：`src/pages/about.astro`
- 洞察列表页：`src/pages/insights.astro`

文案以 `brand/品牌表达系统_V1.md` 为准，改完需同步检查其他页面是否出现同一句话的不同版本。公开页面不要出现手机号、公司名、客户名和内部数据。
