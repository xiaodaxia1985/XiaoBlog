我做小红书和抖音图文，一直卡在排版上。平台自带的编辑器做得比较平，字号几档，颜色一排，模板能换但不能改结构。用它做出来的图和别人的长得一样，读者扫过去记不住是谁发的。我需要的是把一个想法做成一套图。给一张图贴字不够。

## 开源社区寻找解决方案

自己有了需求，先到开源社区找解决方案。因为大概率别人已经比你早遇到这些问题。

我在 GitHub 上找到一个仓库，叫 article2media。它把写好的内容当输入，脚本拼出 HTML，无头浏览器渲染，截图存成图片。同一篇内容能出四个平台：小红书 3:4，抖音 9:16，还有公众号长图和 X 的配图。这些平台的尺寸和排版规则它都预先处理过了。

紧接着是验证这个工具能否按它描述的那样，产出我们预期的结果。我 clone 了代码库，在自己电脑上运行了。结果非常好。

我使用此工具，用它出了第一套图。

## 产出物达到预期，但审美上差点意思

结果出来了：图能出，尺寸对，字也没错，但感觉没有美感，看起来不怎么舒服。

它本来自带 21 套主题。editorial 和 swiss 是杂志风。bauhaus 走几何，pop 撞色，还有一套国潮往页面角上盖朱砂印章。但看起来都不够好。我要的是简洁、干净，重点一眼看得出来的产物。

## 产品要有设计准则

一个让大家用起来舒服的产品，一定遵循了一定的设计原理和准则。

我在移动端交互和网页交互都做过一些东西，两边的基本功是通的。移动端在这些事上被逼得更狠。屏幕小、注意力短，任何一个多余的装饰都会被看见。所以移动端做得好的产品，设计密度和质量普遍高于网页。

移动端里，说到设计，那 Apple 是当世独一档。我前段使用了一个叫 Hark 的 AI 应用，它的对话页让我停了很久，非常惊艳。

改造方向就这样定下来了。把 Apple 和 Hark 这一类移动端的设计准则，搬到 article2media 的 HTML 上。

## 提炼准则，交给 AI 落地

从 Hark 那个截屏，我把它交给 AI，让 AI 提炼出设计准则，把这些设计准则应用到这个工具中。剩下的就是把这个新需求提给 AI，让 AI 来落地实施。

最后把主题收成四套。

## 遇到问题，让 AI 继续解决

改的过程中出了一些实际问题。AI 把卡片倾斜了几度，版面检查报重叠错误。公众号导出时 class 会被丢掉，第一版粘进去后面目全非。磨砂模糊在微信编辑器里时灵时不灵。这些问题喂给 AI，它改完跑一遍检查，过了就继续往下。

## 验证结果，反哺社区

四套主题配上长图、3:4 和 9:16 三种比例，一共十二组，版面检查 0 个错误。同一套结构托住四个出口，换平台只是换画布尺寸和字号。

这个改造我会整理成能合并的形式，提交回上游，回馈开源社区。

这次学到的东西可以重复用。需求明确之后，先去 GitHub 等地方找现成的工具，不要自己从零做，学会站在巨人的肩膀上。工具拿到手，先验证是否满足我们的需求。如果需求满足，有地方需要优化，我们就自己想办法优化。找到解决方案之后，交给 AI 落地实施，遇到具体问题继续让它解决，直到达到要求。最后自己验证完确实挺好，请反哺社区，让新来者继续站在巨人的肩膀上。
